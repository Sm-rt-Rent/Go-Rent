# Security Audit Notes — GoRent

Summary of findings (quick):

- Project currently uses HS256 symmetric JWT signing via `JwtService` which reads `jwt.secrets` from `application.properties`.
- `JwtService` hardcodes 10h token lifetime and derives an HMAC key from a base64 secret.
- `JwtFilter` and `SecurityConfig` are present and wired; filter is added before `UsernamePasswordAuthenticationFilter`.
- `AuthService` issues tokens via `jwtService.generateToken(...)` on login and does not currently support refresh tokens or revocation.
- `application.properties` contains `jwt.secrets = ${JWT_SECRET:...}` — default secret included in repo as fallback (remove for production).
- CORS origins are configurable via `app.cors.allowed-origins` and currently default to localhost origins; actuator health is exposed publicly.

Immediate risks and recommended priorities:

1. Move from HS256 (symmetric secret) to RS256 (asymmetric) in production to avoid sharing signing key across services and to enable key rotation.
2. Remove default JWT secret from `application.properties` and require `JWT_SECRET` (or better: use `GORENT_JWT_PRIVATE`/`GORENT_JWT_PUBLIC`) to be provided via environment or secret store.
3. Implement refresh tokens with persistent storage (database) and revoke/rotate refresh tokens on logout.
4. Ensure token validation checks issuer (iss), audience (aud), expiration (exp), and use short-lived access tokens (e.g., 15m).
5. Protect non-health actuator endpoints and require authentication/whitelist for /actuator/** beyond health.
6. Add rate-limiting for auth endpoints and account lockout/brute-force protections.
7. Add security headers (HSTS, X-Frame-Options, Referrer-Policy, X-Content-Type-Options) and enforce HTTPS at the gateway.
8. Do not log secrets and ensure `.env` or any secret files are ignored by git.
